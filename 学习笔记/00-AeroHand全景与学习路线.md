# AeroHand 全景与学习路线

> 参考：[官方项目](https://github.com/chestnut-robotics/aero-hand-open)、[SDK 说明](https://github.com/chestnut-robotics/aero-hand-open/blob/main/sdk/README.md)。本笔记先建立全貌；具体硬件配置和训练任务以对应版本官方文档为准。

## 1. AeroHand 是什么
Aero Hand Open 是一个开源的、由电机通过绳索驱动的五指机械手项目。它既有真实机械手的机械、电路和固件资料，也有控制、仿真和强化学习的软件。官方介绍为 16 个关节、7 个自由度；关节是可活动的位置，自由度可先理解为可独立控制的运动方向，二者不等同。

## 2. 从下到上的组成
| 部分 | 功能 | 对应资料 |
|---|---|---|
| 机械结构 | 手掌、手指、关节承载和传递运动 | hardware/ |
| 驱动与传动 | 电机拉动绳索，绳索带动手指；理解行程、张力和限位 | hardware/、组装文档 |
| 电路与供电 | 为控制板和驱动部件提供连接、通信和电力 | hardware/、硬件文档 |
| 控制板与固件 | 控制板运行固件，接收并处理指令，与电机交互 | firmware/ |
| Python SDK | 在电脑上连接设备，提供归零、校准、运动控制等接口 | sdk/ |
| ROS 2 | 可选的机器人软件通信与集成方式 | ros2/ |
| 仿真 | 用模型在 MuJoCo 中模拟手及其运动和交互 | sim_rl/simulation/ |
| 强化学习 | 在仿真任务里通过反复尝试学习控制策略 | sim_rl/mujoco_playground/ |

官方 SDK 使用 USB 串口连接主机；在 Windows 下通常表现为 COM 端口。具体供电、接线、传感反馈和固件实现须查对应硬件文档及代码，不应凭这张概览图猜测。

## 3. 看懂两条路线
手动控制：人设定目标 → 电脑上的 Python 程序 / SDK → USB 串口 → 控制板固件 → 电机 → 绳索与手指。设备状态可能通过实现支持的反馈通道回到软件；具体反馈内容需要查协议。

学习控制：仿真环境产生观察 → 策略输出动作 → 仿真手与物体变化 → 环境给奖励并进入下一轮；训练得到策略后可在仿真中测试，部署真机还需要状态获取、动作转换、通信和实物验证。ROS 2 是可选的集成工具，不是每次控制都必经的一层。真实手和仿真有差异，仿真成功不保证真机成功。

## 4. 学习优先级与成果
| 阶段 | 重点 | 掌握标志 |
|---|---|---|
| 0 全貌 | 各部分及信息/动力的流向 | 能画出从程序到手指的链路 |
| 1 基础 | Python 函数、类与数组；电压电流、供电、串口；电机、关节和绳驱 | 能解释 USB 串口与供电的作用，并读懂短例子 |
| 2 真实控制 | 读 SDK 例子，连接、校准、单关节目标、反馈及限位 | 可逐行解释一个官方例子；有实物时按文档安全操作 |
| 3 仿真 | MuJoCo 模型、关节、执行器、状态、时间步 | 在对应环境中观察并解释一个动作 |
| 4 强化学习 | 状态、动作、奖励、回合、策略、训练与推理 | 能解释一轮训练的输入输出，并运行适合设备的示例 |
| 5 部署与整合 | 模型输入输出映射、频率、反馈、仿真到实物差异 | 能画出并核查策略控制真机的数据流 |
| 按需深入 | ROS 2、固件、通信协议、机械设计、视觉 | 根据具体项目目标选择，不必同时精通 |

没有真机可先学基础和仿真；有真机可并行认识硬件及 SDK。先确认电脑和目标再确定实际安装方案，训练依赖和算力以官方具体示例为准。

## 5. 目录地图
`hardware/` 硬件，`firmware/` 固件，`sdk/` 电脑控制接口，`ros2/` 机器人集成，`sim_rl/` 仿真和学习。先理解部件之间如何连接，再逐个阅读；不要只凭目录名判断具体实现。

## 6. 下一课建议
以一条具体命令为线索，先认识硬件各部件和控制链路，再进入 SDK 示例；若没有实物，则先用图或仿真建立直观认识。学习前确认用户是否有实物、编程基础、电脑配置和主要目标。
